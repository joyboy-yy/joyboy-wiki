# 浏览器与接口工具分工

Chrome DevTools、OpenAPI 查询和 Playwright 都涉及前后端联调，但解决的问题不同。

## 能力边界

| 工具能力 | 最擅长回答 | 不适合替代 |
|---|---|---|
| OpenAPI 查询 | 接口路径、方法、参数、DTO/VO、响应和权限是什么 | 实际接口是否正常运行 |
| Chrome DevTools | 页面为什么坏、哪个请求失败、Console 有什么错误 | 可重复回归测试 |
| Playwright Test | 用户流程以后是否仍能工作 | 根因分析和后端内部逻辑测试 |
| Playwright CLI | 一次性驱动页面、探索流程和快速验收 | 长期可维护的测试资产 |

## 选择顺序

```text
接口契约问题 -> OpenAPI
页面行为需要重复验证 -> Playwright Test
页面失败原因不明 -> Chrome DevTools
没有本地用例但需要一次验收 -> Playwright CLI
```

## 使用门禁

### OpenAPI

- HTTP 路径、参数、schema、权限或前后端类型发生变化。
- 前端与后端对字段含义存在分歧。
- 先搜索接口，再读取精确 operation 和 schema；仅在服务文档已更新时刷新索引。

### Chrome DevTools

- 页面白屏、登录态异常、Console 报错、请求状态异常。
- Playwright 失败但无法从断言判断原因。
- 聚焦检查目标页面、具体失败请求和相关 Console，不全量抓取噪声。

### Playwright

- 页面、路由、权限、表单、状态机或响应式布局发生变化。
- 优先运行聚焦用例；没有用例时先完成一次交互验收，再决定是否沉淀。

## 常见错误

- 纯 Service 修改却启动浏览器。
- 只看 OpenAPI 就声称接口运行正常。
- Playwright 失败后反复重跑，不查看 Network 和 Console。
- 用 Chrome 手工点通一次就声称有回归覆盖。
