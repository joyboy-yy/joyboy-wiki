# MCP 能力与使用门禁

MCP 为 Agent 提供外部能力，但不会自动形成正确工作流。MCP 是被动工具，Skill 才负责判断何时调用。

## 适合 MCP 的能力

- 需要结构化访问远程或本地服务。
- 调用参数和返回结果可以形成稳定契约。
- 手工命令容易泄露凭据或产生重复胶水代码。
- Agent 需要查询数据库、接口文档、浏览器状态或业务系统。

## 不适合 MCP 的情况

- 本地文件读写已有原生工具。
- 一条项目命令已经能确定性完成。
- 只是为了包装静态说明文档。
- 工具调用会产生不可控写操作且缺少审批。

## 四级门禁

| 级别 | 条件 | 行为 |
|---|---|---|
| L0 不调用 | 纯逻辑、文档或本地源码足够 | 使用源码和项目命令 |
| L1 只读查询 | 需要接口、schema、浏览器或数据库事实 | 只读 MCP |
| L2 受控验证 | 需要启动服务、发送请求、驱动页面 | 明确范围和清理方式 |
| L3 写操作 | 修改数据、发布、删除或调用真实外部服务 | 必须审批、备份和审计 |

## 配置隔离

- 团队文档只描述“需要接口契约查询能力”。
- 个人 Skill 可以写“若存在 house-openapi 则优先查询”。
- MCP URL、密码、令牌、本机路径存入本地配置或环境变量。
- 配置文件必须被 Git 忽略，并定期检查是否误入历史。

## 工具治理指标

- 每类任务平均 MCP 调用数。
- 无效调用、重复调用和调用失败率。
- 工具结果是否真正改变了测试或实现决策。
- 只读与写操作占比。
- 因工具不可用导致的阻塞次数。

## 核心原则

> 不因“工具存在”而调用，只因“当前证据缺口需要该能力”而调用。
