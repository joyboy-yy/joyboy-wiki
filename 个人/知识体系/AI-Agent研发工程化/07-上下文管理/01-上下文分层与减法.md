# 上下文分层与减法

现代 LLM 能理解复杂项目，但仍会被重复、冲突和陈旧上下文误导。上下文优化的重点是提高信息密度，而不是无限增加规则。

## 四层上下文

| 层级 | 内容 | 加载策略 |
|---|---|---|
| 常驻上下文 | 安全、命令入口、提交边界、阅读路由 | 自动加载，极短 |
| 条件上下文 | Java、前端、SQL、测试规则 | 按变更类型读取 |
| 任务上下文 | 当前源码、diff、日志、接口、数据 | 执行中动态获取 |
| 历史上下文 | 复盘、知识图谱、设计决策 | 需要时检索 |

## 做减法的判断

- 同一规则出现三次以上，应确定唯一所有者。
- 能从清单或命令实时获得的信息，不复制到入口。
- 长示例放专项文档，不放自动加载文件。
- 个人工具说明不进入团队项目事实。
- 已有 Skill metadata 时，不在入口复制触发词。
- 精确 bug 优先读目标源码，不先加载整套架构文档。

## 上下文污染来源

- 过期版本号和端口。
- 多语言镜像语义漂移。
- 相互矛盾的代码示例。
- 复制的命令清单与实际任务文件不一致。
- MCP 工具全部常驻导致工具选择噪声。
- 长时间会话中保留已完成任务的细节。

## 控制手段

- 入口文件使用条件阅读表。
- 项目事实提供权威来源表。
- 用 Grep/Glob 精确检索，避免全库读取。
- 大型探索交给子代理，主上下文只接收结论。
- 任务完成后压缩为修改、证据、风险和后续。
- 用知识库保存长期方法，不依赖会话记忆。

## 衡量指标

- 自动加载入口的行数和 token 数。
- 完成任务前读取的无关文件数量。
- 因规则冲突导致的返工次数。
- 工具调用成功率与无效调用率。
- Agent 最终报告中未验证风险的准确度。

## 目标状态

> 常驻上下文只包含“必须立即知道的约束”，其余信息在正确时机被准确检索。
