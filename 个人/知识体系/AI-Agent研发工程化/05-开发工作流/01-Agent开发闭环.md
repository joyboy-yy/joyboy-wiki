# Agent 开发闭环

标准工作流的目标是让 Agent 在信息不足时先调查，在完成代码后提供可验证证据，而不是只输出一段实现。

## 八阶段闭环

| 阶段 | 核心动作 | 产出 |
|---|---|---|
| 1. 意图识别 | 区分提问、规划、实现、排障、评审、提交 | 明确任务类型 |
| 2. 约束加载 | 读取入口和变更相关规则 | 适用约束集合 |
| 3. 现状调查 | 查源码、配置、清单、数据和已有测试 | 事实与根因假设 |
| 4. 任务拆解 | 按依赖和边界拆分步骤 | 可执行任务列表 |
| 5. 最小实现 | 选择最小正确修改，不顺便重构 | 目标 diff |
| 6. 分层验证 | 聚焦测试优先，跨边界时升级 | 命令与结果 |
| 7. 风险审查 | 检查回归、权限、数据、安全和未覆盖项 | 风险清单 |
| 8. 知识沉淀 | 更新项目事实、Skill 或个人复盘 | 可复用资产 |

## 调查优先级

```text
明确错误/符号 -> 直接查目标源码
架构/模块问题 -> 查项目事实和依赖关系
API 契约问题 -> 查 Controller/DTO/VO 和 OpenAPI
数据问题 -> 查 Mapper/SQL/schema/代表性数据
页面问题 -> 查路由、组件、API 层、Network/Console
```

## 工具升级原则

先使用成本最低且最接近事实的能力：

1. 文件读取、搜索和 diff。
2. 项目任务命令与聚焦测试。
3. 结构化只读工具，如 OpenAPI、数据库 schema。
4. 启动服务、API 冒烟和浏览器流程。
5. 全量构建、全量回归或真实外部集成。

## 完成定义

- 用户目标已实现，而不只是代码已修改。
- 变更范围清晰，没有覆盖他人工作。
- 最小验证已运行且结果准确。
- 跨越的边界都有证据。
- 未验证内容和剩余风险明确。
- 需要长期保留的信息进入正确知识层。
